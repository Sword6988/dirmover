# 用户数据转移工具（Python 版）

把 Windows 当前用户的个人文件夹（文档、图片、音乐、视频、下载、桌面、收藏夹等）
从系统盘迁移到其它磁盘，并同步修改注册表，使系统继续正常工作。
效果等同于资源管理器「属性 → 位置 → 移动」，但可以一次处理多项。

本工具是一个**独立的 Python 实现**（tkinter + 标准库，运行时零第三方依赖）。
界面结构、交互与行为规范见 `docs/ui-skeleton.md` 与 `docs/审计报告.md`。

> **关于「对齐」的口径**：本工具**不做「已修复全部缺陷」这类全覆盖式承诺**。
> 与早期版本存在差异、或有意不跟随早期版本行为的条目，一律在文末「**已知边界**」中
> 逐条列出并说明原因；不在该节列出的，即为已对齐项。

## 快速开始

### 直接运行（推荐）

```
dist/DirMover.exe        # 双击运行，单文件免安装（约 12.5 MB；精确字节数以 build.py 的输出为准）
```

- 64 位 Windows 10 及以上（Win11 实测通过）。**这是交付 exe 的门槛**：exe 内嵌
  CPython 3.14，而 3.14 已不支持 Win7/8.1，故**打包产物不能在 Win7/8.1 上运行**；
- 需要**管理员权限**（写入 `HKCU` 的 `User Shell Folders` 并重启资源管理器）
- 日志目录 `logs\`、恢复快照 `backups\` 自动生成在 exe 旁边，绿色便携；
  程序**不做设置持久化**，每次启动都使用内置默认值

### 从源码运行

```bash
cd pydm
python run.py              # 图形界面
python run.py --scan       # 只读列出各文件夹当前位置与状态
python run.py --dry-run    # 完整规划但不做任何改动
```

依赖：**仅 Python 标准库**（tkinter 打包即含），无第三方运行时依赖。
打包则需要 `PyInstaller`（版本已固定在 `requirements-build.txt`，用法见下文「开发与构建」）。

> **两种运行方式的 Windows 门槛不同**，请以实际使用的方式为准：
>
> | 方式 | Windows 门槛 | 依据 |
> |---|---|---|
> | **源码运行**（`python run.py`） | **Windows 7 及以上**（64 位） | `run.py` 的 `MIN_SUPPORTED_MAJOR = 6` / `MIN_SUPPORTED_MINOR = 1`，版本低于此才拒绝启动，提示语为「仅支持 Windows 7 及以上系统」；**源码运行不拦 Win7/8.1** |
> | **交付 exe**（`dist/DirMover.exe`） | **Windows 10 及以上**（64 位） | 内嵌 CPython 3.14，该解释器本身已放弃 Win7/8.1 |
>
> 解释器版本另有一层要求：程序用到 `dataclass(slots=True)`，**源码运行**需 Python ≥ 3.10；
> **打包**则**强断言**构建解释器精确等于 3.14（见「开发与构建」），故源码运行也建议用 3.14。

## 使用要点（与早期版本一致的行为）

- **目标根目录**：下拉固定提供每个非系统固定磁盘的 `<盘>:\UserData`，不可自由填写；
- **创建当前用户目录**：勾选后每项目标为 `<目标根>\<用户名>\<文件夹基名>`，
  不勾选则为 `<目标根>\<文件夹基名>`；
- **单屏布局（零导航）**：目标根目录 / 项目列表 / 操作条 / 状态栏自上而下常驻一屏，
  不切页、不弹新窗口；界面内**没有**日志区域（过程详情只写入 `logs\` 文件，
  出错或有失败项时状态栏会出现「打开日志目录」入口）；
- 快捷键：`Ctrl+Return` 触发「开始转移」（表格内回车仍是切换勾选）；
- 内置固定行为：执行前弹出确认对话框（给项数 + 目标的摘要，规模在执行时统计；
  本次将转移的行在列表中以浅蓝底标出，可逐行核对）；转移成功后询问是否重启
  资源管理器（原「基本参数」页签的选项已内置为默认开启，无需手动设置）；
- **执行中可控**：主按钮在执行中切换为「停止」，点击即逐项收尾
  （已完成的项目保留，未完成的源文件不删除、注册表不写入）；
- **不做规模预统计**（2026-10-14 产品决策）：勾选后零读盘——待统计内容动辄
  数十万文件，勾选后自动扫描是分钟级开销；每项多大由引擎在执行时权威扫描，
  并经空间闸门（内容 × 1.05 + 64 MB 余量 vs 可用空间）把关；
- 可转移项目：我的文档、收藏夹、我的图片、我的音乐、我的视频、下载目录、桌面
  （Cookies/缓存/历史/临时目录等高风险项已按需求整体移除）；
- **状态列文案精简**：未扫描时只显示「待转移」，避免行尾被硬裁；
- **列宽按内容自适应**：各列宽度由「表头 + 每行文字」的实测宽度与角色配额算出
  （路径列吃余量、名称列不白占空白、状态列永不裁字），窗口缩放与数据变化后自动重排；
  路径被压到放不下时，鼠标悬停该单元格给出完整文本（表格显示值不变）；
- **失败可操作**：结果弹窗逐项列出原因，状态栏出现「打开日志目录」直达完整日志；
- **启动默认值**：默认**全选**所有项目、目标根目录默认 **`D:\UserData`**、
  默认勾选**创建当前用户目录**（若 D 盘不存在，目标根目录会自动回落到首个可用磁盘；
  完全没有非系统固定盘时给出明确空态提示并禁用主按钮）；
  程序不读写任何配置文件，每次启动都是这套默认状态。

## 转移流程（安全模型）

1. **规划**：读取注册表当前位置 → 与目标合成计划 → 逐项校验
   （目标不为空、是绝对路径、各级片段不是 Windows 保留名也不以点/空格结尾、
   不是系统目录、不在源之内）。该校验在**引擎层**执行，
   界面与命令行（`--dry-run`）走的是同一条防线。
2. **执行**（每项，顺序不可颠倒）：
   - **同盘且目标不存在** → 原子 `os.rename`，一步到位、无中间态；
   - 否则走安全通道：
     1. **清点源目录**：枚举全部文件（大小 + 时间戳）与**空目录**、符号链接/目录联接；
        枚举过程中任何读不到的地方都视为失败，直接中止（不漏项才敢删源）；
     2. **重建目录结构**（含空目录）与链接（按原样重建，重建不了即整体失败）；
     3. **复制**：逐文件分块读写，**边复制边算源内容摘要**；稀疏文件按稀疏方式
        复制、硬链接按 inode 在目标重建（不支持则回退完整复制）；
        同名冲突**绝不静默覆盖**——内容一致则复用，不一致则另存为 `name (1).ext`，两份都保留；
     4. **校验（源 ↔ 目标全量对照）**：目标内容摘要 = 源摘要、目标大小 = 源大小、
        源自清点以来未被改动、且「源集合 − 清单集合」的差集为空（目录/文件/链接分别比对）；
     5. 校验通过 → **写注册表**（同名多值一起写，任一失败即回滚本项，杜绝
        「权威值名已改、GUID 别名未改」）；
     6. 注册表写成功 → **最后**删除源目录。
   - 任一步失败：**源目录一定还在**，界面明确给出失败原因；每项的阶段都登记在
     `backups\intent.json`，进程被中断（关窗/断电）后下次启动会提示，并可用快照一键回滚注册表。
   - 「停止」按钮与窗口关闭（X）都走同一收尾路径：**先等当前项收尾**（写完并校验、
     或失败保全源）再退出，等待上限 **60 秒**（`ui/main_window.py::_EXIT_TIMEOUT_MS`）。
     超时会记一条日志并**强制退出**——此时后台线程可能在某个冗长步骤中途被进程结束
     打断（最典型的是删除超大的源目录）。**数据不会丢**：删源只发生在一项**校验通过
     之后**，被打断的最坏结果是源目录留下残骸，而不是目标缺内容；该残骸会在下次启动时
     按 `backups\intent.json` 的记录提示处理。*（早前这里的表述是「不会停在删除中途」，
     强于实现，已按实际口径改写。）*
3. **善后**：重启资源管理器使改动生效（在后台线程执行，界面不冻结）。

> **关于备份**：**每次执行**（`transfer.TransferEngine.execute()`）**开头会一次性**
> 把本次计划涉及的**全部**注册表原始值存成**一份** JSON 快照落盘到 `backups\`；
> 执行过程中逐项使用的是这份快照的**内存态**（用于失败时回滚本项），**不会逐项落盘**。
> 同一目录下的 `intent.json` 是「本次转移走到哪一步」的事务日志，
> 正常结束会自动删除，**它还在就说明上次没走完**——启动时会提示怎么处理。
> 这两样都不改动任何用户文件。这是 Python 版新增的保险机制，早期版本没有。
>
> ⚠ **回滚的边界**：快照回滚（含「一键回滚」）**只还原注册表值，不搬回文件**——
> 文件已经搬走的部分不会因回滚而回来。要把文件也搬回去，请走「**恢复系统默认值**」
> （即下节那条完整路径：搬回 + 校验 + 改回默认路径；这与早期版本一致，不是新增能力）。

### 「恢复系统默认值」做什么

与早期版本**一致**：这是**完整恢复**，不只是改注册表。

1. 先把内容从当前位置**搬回**系统默认目录（`C:\Users\<当前用户>\Documents` 等），
   走的是**与「开始转移」完全相同**的安全事务——复制 → 源↔目标全量校验 →
   写注册表 → **校验通过才删源**；
2. 再把注册表指回该默认目录（含 GUID 别名一并同步）。

安全边界（早期版本没有这些）：

- **空间不足**的项**单独阻断**并报出缺多少，其余项照常执行——不会因一项放不下而全部停下；
- 注册表指向**盘根 / 系统目录**，或**与默认目录互为祖先/后代**时，该项直接拒绝
  （否则会自我嵌套复制、或在删源时连带删掉默认目录）；
- 源目录**已不存在**时降级为「仅修正注册表」——注册表仍会被改对，且不动任何文件
  （早期版本在这种情况下会跳过整项，注册表永远修不回来）；
- 改动前照例存注册表快照到 `backups\`，可一键回滚（**仅还原注册表值，不搬回文件**；
  要搬回文件走的就是本节这套「完整恢复」）。

> 与早期版本（只改注册表、不搬文件）的差别：那样改完注册表后 C 盘默认目录可能是空的，
> 指针与数据分家、比不恢复更糟。现为完整恢复。

对比早期版本修复的关键点：

| 早期版本缺陷 | Python 版做法 |
|---|---|
| 整目录复制后无条件删源目录，复制失败也删 | 复制 + **源↔目标内容摘要与集合全量校验**通过才删，失败不影响源 |
| 倒计时到点后事件永远不会触发（P1） | 自动执行功能已整体移除，不存在此路径 |
| 磁盘列表为空时拼出非法正则崩溃 | `validate_destination()` 显式校验，给出中文错误 |
| 恢复默认时源目录不存在 → 整项跳过，注册表永远修不回来 | 降级为「仅修正注册表」，把注册表改对且不动文件 |
| 无条件强杀 `explorer.exe` 进程 | 仅在设置允许时优雅重启，失败不影响结果 |
| 关闭按钮失效（负常量缺陷） | 关闭按钮接入统一收尾路径，执行中退出也会安全收尾 |

## 开发与构建

### 构建工具链（可复现构建，审计 P2-18）

运行时**零第三方依赖**（仅标准库）；只有「打包 exe」这一步需要 PyInstaller，
版本已在 `requirements-build.txt` 中固定，以保证不同机器产出一致。
构建须在**隔离的 Python 3.14 venv** 中进行（`build.py` 会强断言解释器与
PyInstaller 版本，见下）：

```bash
cd pydm
py -3.14 -m venv .venv-build                                          # 用 Python 3.14 建隔离 venv
.venv-build\Scripts\python -m pip install -r requirements-build.txt   # 固定版本：pyinstaller==6.22.2
```

`build.py` 在打包前后会做下列断言，避免出现「版本号对不上 / 工具链悄悄变了」：

1. **解释器版本（强断言）**：构建解释器次版本必须**精确等于** `tools/ci_check.py`
   的 `EXPECTED_PYTHON`（当前 **3.14**）——exe 内嵌的就是该解释器的 CPython，用别的
   次版本会打出与「内嵌 CPython 3.14」声明脱节的产物（历史上曾用 3.13 打出内嵌
   `python313.dll` 的 exe）；不符即 `[FAIL]` 拒绝打包。**运行时**下限另记：程序用到
   `dataclass(slots=True)`，**源码运行**需 Python ≥ 3.10；
2. **PyInstaller 版本（强断言）**：必须**精确等于** `requirements-build.txt` 里的
   `pyinstaller==6.22.2` pin（单一真源）；不符时提示执行
   `python -m pip install -r requirements-build.txt`；
3. **版本号唯一真源**：`build_version.txt` 只是**模板**（含
   `__APP_VER_TUPLE__` / `__APP_VER_4__` 占位符），真实版本号取自
   `docmover/constants.APP_VERSION`，打包时渲染到 `build_work/version_info.txt`；
   模板里若混入手写版本号（占位符残留）会直接中止，防止打出错误版本；
4. **打包后自检（强断言）**：产物生成后自动执行 `tools/verify_release.py`
   （PE / 内嵌解释器 / 图标逐帧 / 版本资源 / 产物↔源码同源），任一不符即构建失败
   （退出码非 0），详见「打包后自检」。

### 一键打包

```bash
cd pydm
python build.py            # 输出 ../dist/DirMover.exe（--keep 可保留中间产物）
```

- 打包参数含 `--noupx`（禁用 UPX：降低杀软误报与解包异常）；
- 打包前会按**固定文件名**清理 `dist/` 中已知的历史交付物
  （更名前的一代产物 `DocMover.exe`），**不通配删除**，绝不误伤交付物 `DirMover.exe`；
- `dist/` 的**交付物只有 `DirMover.exe`**；`dist/logs/` 是 exe 运行时自动生成的
  日志目录（**非交付物**），打包脚本既不生成也不清理它；
- 产物属性：x64 / GUI 子系统 / `requireAdministrator` / 版本随 `APP_VERSION`；
- 打包**成功后自动自检**（`tools/verify_release.py`）：断言产物是 x64/GUI/提权、图标逐帧
  内嵌、版本资源与 `APP_VERSION` 一致、exe 内 PYZ 字节码与当前源码同源；失败即退出码非 0；
- 须在**隔离的 3.14 venv** 中运行（`build.py` 强断言解释器与 PyInstaller 版本，见上）。

### 本地门禁与 CI（审计 P2-23）

仓库提供一层零依赖的本地门禁 `tools/ci_check.py`（编译 + 全量单测 + 红线守卫），
既能在提交前本地自查，也能直接挂到任意 CI：

```bash
cd pydm
python tools/ci_check.py    # 全部通过输出 [OK] 并返回 0；任一失败返回非 0
```

红线守卫包括：界面代码不得出现字面色值 / 几何字形、`config` 不得持久化、
**交付树无编译缓存**（不得残留 `__pycache__` / `*.pyc`）、**文本文件统一 LF**（守卫：交付树内
`.py/.md/.txt/.yml/.yaml/.gitattributes` 出现任何 `\r` 字节即失败）、
**图标 `units` 无二次缩放**（守卫：界面代码的 `units=` 实参右侧不得含 `px(`，
强制「units 是设计单位」这一口径，见 `docs/ui-skeleton.md` §5）。
仓库已附 `.github/workflows/ci.yml`
（windows-latest + Python 3.14），push / PR 时自动执行同一门禁 —— 本地与 CI
跑的是**同一个脚本**，不存在「本地过了、CI 挂了」的双份逻辑。

> 这些红线守卫是**朴素判定**（正则 / 关键字 / 字节扫描），为确保不漏报而偏向
> **宁可误报**：例如用 f-string 拼接字面色值、`getattr` 间接调用持久化接口等手段
> 可以绕过它们。这是**有意的设计取舍**——守卫防的是**无意回归**，不是恶意对抗；
> 遇到误报时按提示改写成等价但更直白的写法即可，不必调松守卫。

### 发布洁净度

门禁**不得污染交付树**。此前 `check_compile()` 用 `py_compile.compile(path, doraise=True)`
而不传 `cfile`，`.pyc` 会被写进源文件旁的 `__pycache__`——**每跑一次门禁就新生成一批**；
仓库虽有 `.gitignore` 规则，但**本机当前不是 git 工作树**（`git rev-parse --is-inside-work-tree`
报 not a git repository），忽略规则不生效，整包拷走会把这些缓存一起带走。
现已改为内置 `compile(source_bytes, path, "exec")` 只做语法编译、不落盘。
此后（审计 E1）又新增「**交付树无编译缓存**」守卫（扫 `__pycache__` 目录与
`*.pyc`/`*.pyo`，并排在单元测试**之后**复查，防止测试子进程又写出缓存）；
`tools/ci_check.py` 现共输出 **8 项**（编译 + 单测 + 无编译缓存 + 5 条红线守卫），
以脚本自身输出为准；判定口径、输出格式与退出码不变。

同理，交付前可自查一遍并清掉历史遗留的编译缓存：

```bash
cd pydm
python tools/ci_check.py                       # 跑完应不再新增 __pycache__
find . -type d -name __pycache__ -prune -exec rm -rf {} +   # 清理历史遗留（可随时重新生成）
```

### 打包后自检（审计 §5.3）

打包成功 ≠ 产物完好。`build.py` 在产物生成后会**自动调用** `tools/verify_release.py`
做一遍**只读**核验，把它当作**构建断言**：任一不符即构建失败（退出码非 0），
把原本靠人工核验的发布关键属性固化下来。核验项：

1. **PE 头**：x64（`Machine=0x8664`）/ GUI 子系统 / 内嵌 `requireAdministrator` 提权清单；
2. **内嵌解释器**：含 `python3XX.dll`（XX 取自 `tools/ci_check.EXPECTED_PYTHON`，与构建
   断言同源）、且**不含**更早次版本 DLL——防「文档声称某版本、实物却是另一版本」；
3. **图标逐帧内嵌**：`assets/app.ico` 的每一帧像素载荷都在 exe 中；
4. **版本资源**：`FileVersion` / `ProductVersion` / `FileDescription` / `ProductName` /
   `CompanyName` / `InternalName` / `OriginalFilename` 与 `docmover.constants`
   （唯一真源）逐字段一致；
5. **产物↔源码同源**：exe 内 PYZ 里若干关键模块的代码对象与当前源码**逐字节一致**
   （比「看文件时间戳」强得多，可排除「改了源码但 exe 是旧的」）。

该核验**不运行** exe（避免 UAC 提权与真实改注册表），可随时单独执行、复验任一产物：

```bash
cd pydm
python tools/verify_release.py               # 默认核验 ../dist/DirMover.exe
python tools/verify_release.py --exe <路径>  # 指定产物
```

> 第 5 项依赖 PyInstaller 读取 exe 内归档，在**未装 PyInstaller** 的环境里降级为
> `[warn]` 跳过（其余项照常核验），故非构建机也能直接跑；第 4 项走 Windows 版本 API
> （`ctypes`），零第三方依赖。

## 已知边界

- **权威值名与 GUID 别名会一并写入**，避免「资源管理器显示 A、系统实际认 B」。
  两类形态要分清，别混为一谈：
  - **「传统值名 + GUID 值名」**（如**我的文档**：权威值名 `Personal`，
    别名 `GUID_DOCUMENTS`）——见 `constants.py` 的 `documents` 规格；
  - **「两个 GUID 值名」**（如**下载目录**）：Win10+ 下它的**权威值名本身就是 GUID**
    （`GUID_DOWNLOADS`，`{374DE290-…}`），别名是**另一个 GUID**（`GUID_DOWNLOADS_ALT`），
    **并不存在传统值名**——见 `constants.py` 的 `downloads` 规格。
- 符号链接 / 目录联接**按原样重建**（不复制其指向的内容）；重建不了就整体失败、
  保留源目录并告知，绝不静默丢弃；
- **稀疏文件**按稀疏方式复制（跳过全零块并对目标打稀疏标记），**硬链接**按原
  inode 在目标重建为硬链接（审计 P2-5/P2-6，避免「展开后体积暴涨」）；
  仍属尽力而为：目标卷不支持稀疏标记或硬链接时会**回退为完整实体复制**，
  结果正确但目标占用可能高于预期；
- **稀疏判定的粒度是 1 MiB 块**：只对「整块全为零」的块做空洞跳过；块里含少量
  非零数据时会**整块写入**，因此目标的**分配量可能略大于源**（例如源 128 KB、
  目标约 1 MiB 的情形）。这只影响「占盘大小」的观感，**内容逐字节一致、正确性
  不受影响**——请勿把「目标占盘比源大」误判为复制出错；
- **超长路径**（≥ 240 字符）会自动加上 `\\?\` / `\\?\UNC\` 前缀读写，
  绕过 MAX_PATH=260 限制（不影响界面展示的路径文本）；
- 程序不支持在 Windows PE 下运行（与早期版本一致）；
- **混合 DPI 多显示器**：进程按 **system-DPI-aware** 声明，启动时用系统 DPI 算出
  一套缩放系数。把窗口从 100% 缩放的显示器拖到 150% 的副屏时，Windows 会对整个
  窗口做**位图拉伸**，界面因此**发虚**；但布局与字号**不会错乱、也不会脱节**
  （所有尺寸都过同一套逻辑像素换算）。彻底解决需要改为 per-monitor-v2 感知并
  响应 `WM_DPICHANGED` 重建主题，属后续产品取舍；
- 单实例：重复启动会提示退出（用命名互斥体实现，无早期版本的进程列表竞态）。
  互斥体位于 `Local\` 命名空间，即**按登录会话**隔离——同一会话内只允许一份
  （以管理员身份启动的实例也共享它），多用户 / 多会话（快速切换用户、RDP）
  各能运行一份。
- **目标根目录不会显示为中文别名**：早期版本界面有「个性化目录别名」输入（默认「用户目录」），转移完成后在**目标根目录**（如 `D:\UserData`）写 `Desktop.ini`
  （`LocalizedResourceName=别名` + `IconResource` + Hidden/System），使资源管理器把该目录
  显示成「用户目录」——这样磁盘上保持英文/数字物理名（早期版本提示语与它的 `[A-Z]:\\[A-Z0-9]+`
  校验都只接受英文数字），用户看到的是中文。本工具**未接线**该逻辑
  （`shell.write_desktop_ini` 现为预留接口，生产链路未调用），故该目录显示物理名
  （如 `UserData`）。不接的原因：它会**给该目录加 Read-only 且没有还原路径**
  （「恢复系统默认值」只回滚注册表与搬回文件，不碰任何文件属性，也不删 `Desktop.ini`），
  接入前须先设计属性还原。**已决策：不做**（纯外观、收益不完整——用户名层仍是英文、且会破坏「目标根命名与早期版本一致」的不变式）。
- **别把上一项与文件夹的本地化显示混为一谈**：`Documents` ↔「文档」这一层的本地化与
  Desktop.ini 写入**无关**——它由 Windows 自带的 `Documents\desktop.ini`
  （`LocalizedResourceName=@%SystemRoot%\system32\shell32.dll,-21770`）承担，该文件随目录
  整树复制被一并带走。早期版本与本工具在这一点上**行为相同**（两者都整树复制、都不排除它），
  因此这一层**没有**差异。
- **资源管理器重启守卫（审计 P2-2 已修：判定读 HKLM）**：对比表「仅在设置允许时优雅重启」
  现在描述的就是**实际行为**。开关的真值位置按 Microsoft 文档是
  `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\AutoRestartShell`
  （`REG_DWORD`，取值 `0|1`，**默认 1**；读 HKLM 不需要管理员权限）。
  早期实现误读了 `HKCU` 下的同名值——而该子键里根本没有 `AutoRestartShell`
  （实测只有 `RestartApps` / `ExcludeProfileDirs` / `BuildNumber` / `FirstLogon` /
  `ParseAutoexec`）——导致判定恒为假、`taskkill` 分支在生产里**永远执行不到**：
  界面问「是否重启资源管理器」，用户点「是」，拿到的却是「已跳过」。这是**读错 hive**
  的口径缺陷，不是刻意保守。现行语义：

  * 值 `=1`，或值**不存在**（Windows 默认即为 1）→ 允许重启；
  * 值 `=0`（管理员显式关闭了自动重启）→ 跳过，并把原因如实报给用户；
  * 读取失败（权限 / 句柄 / 损坏）→ 跳过（**未知时不冒险**，fail-closed）。

  放开可达性后，安全性由三件事共同保证：**只结束本用户会话的 explorer**
  （`taskkill /fi` 用户过滤、参数以数组形式传递而非字符串拼接）、结束后**复查进程是否
  回来**、没回来就用 `ShellExecuteExW` 以**未提权令牌**主动拉起（避免把管理员完整性级别
  扩散给之后从桌面启动的程序）。在默认系统（`AutoRestartShell=1`）上 Windows 本身也会把
  shell 拉回来，上述兜底属双保险。用户唯一可感的变化：点「是」之后桌面与任务栏会**短暂
  消失再回来**。
